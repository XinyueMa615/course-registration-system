# 课程注册系统（新项目）

这是从零建立的独立项目，不依赖原来的 `course-registration-system` 代码。旧 Ingres 目录以只读 MySQL 演示库 `course_catalog_demo` 模拟；新系统的可修改数据在 `course_registration_v2`。目前完成学生登录与选课、教师认领教学班、教务档案与学期管理、选课截止处理、本地模拟计费发送/重试，以及教师成绩录入和学生成绩单。草稿不占名额；提交时在事务中检查先修课、主选时间冲突、开放时间和容量。开放期内学生可确认删除课表，已占名额在同一事务中释放。

## 本机启动（macOS + VS Code）

1. 在 VS Code 打开本目录 `course-registration-system-v2`，终端中执行：

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. 确认 MySQL 正在运行。在 MySQL Workbench 中，用有建库权限的账号依次运行 `database/01_catalog.sql`、`database/02_registration.sql`、`database/03_demo.sql`。已有同名演示数据库时，不要重复运行 `03_demo.sql` 覆盖正在做的选课数据；先运行 `database/04_verify.sql` 检查即可。

3. 在 Workbench 打开 `database/05_permissions.sql.example`，把占位密码替换成新的强密码，再执行。该账号只可读取课程目录，并可读写业务数据库。如果该账号已存在且密码不对，请在 Workbench 中单独修改密码；`CREATE USER IF NOT EXISTS` 不会重置旧密码。

4. 将 `.env.example` 复制为 `.env`，填上第 3 步的数据库密码，将 `APP_SECRET` 换成自己生成的随机长字符串（至少 32 字符），并设置本地演示用的统一初始密码 `INITIAL_ACCOUNT_PASSWORD`（至少 10 位）。`.env` 已被 `.gitignore` 排除，不能上传 GitHub。例如：

   ```bash
   cp .env.example .env
   python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
   ```

5. 演示数据已有学生 `S001`，但没有默认登录密码。创建账号（运行时交互输入密码，不写到命令历史）：

   ```bash
   python3 -m scripts.create_account nancy STUDENT --person-id S001
   ```

6. 启动服务：

   ```bash
   uvicorn app.main:app --reload --port 8001
   ```

   打开 <http://127.0.0.1:8001/> 登录；学生留在学生工作台，教师和教务员会自动进入各自页面。学生页面按“课程与选课／我的成绩单”切换，教师页面按“教学班／名单与成绩”切换，教务页面按“学期与截止／计费状态／学生档案／教师与资格”切换。所有页面都使用同一个 8001 端口。API 文档在 <http://127.0.0.1:8001/docs>。原项目若占用 8000 端口，新项目的 8001 端口不会与其冲突。

学生选课页面会在填写课表时每 20 秒检查一次已选教学班的最新名额，并在主选已满或关闭时提示调整；点击提交前还会再次检查。真正占用名额的并发校验仍在数据库事务中进行，页面提示不能替代它。开放期内“删除课表”会先请学生确认，再删除选择并释放已提交主选的名额；截止后的最终课表不能删除。

## 教师端演示

演示库的教师 `P001` 已有 `CS101` 等课程的任教资格。先为它创建教师账号（交互输入密码）：

```bash
python3 -m scripts.create_account teacher1 PROFESSOR --person-id P001
```

打开 <http://127.0.0.1:8001/professor> 登录。原始演示数据的七个教学班都已预分配教师，因此最初只会看到“已认领”。要体验认领一个新班，可在 Workbench 用管理员连接执行 `database/06_teacher_demo_option.sql`。它只追加一个未认领的 `CS101-02` 班，不修改现有学生课表。刷新教师页面后即可认领；重复执行不会重复添加该班。真实课程目录仍由外部系统提供，本应用运行时不会写入该目录。

认领会校验教师资格、选课时间、是否已有教师、教师本人其他教学班的时间冲突；教师只能退出自己认领的班。关闭选课后的认领与退出均被拒绝。

选课开放期间，教师可在自己认领的教学班点击“查看报名名单”，查看已经提交课表的学生；草稿学生不在名单中。教师不能查看其他教师的报名名单。

学期正式关闭后，教师可在自己已认领且未被取消的教学班点击“查看名单与成绩”，查看最终学生名单并录入 A、B、C、D、F 或 I。重复保存相同成绩不会新增记录；修改成绩会记录原成绩、新成绩、教师及时间。学生页面“我的成绩单”只显示本人的已完成且已录入成绩的课程。演示学期 `2026FA` 尚未截止，暂时无法查看最终名单或录入成绩；请勿为了演示而提前关闭正在使用的学期。

## 教务端演示

新建一个教务员账号，密码在终端交互输入：

```bash
python3 -m scripts.create_account registrar1 REGISTRAR
```

打开 <http://127.0.0.1:8001/registrar> 登录。这里可以新增、查看、修改和确认删除学生/教师档案，并为教师添加或移除课程任教资格。新增时学号/教师编号由系统生成，同时自动建立登录账号（用户名为编号的小写形式）；新建学生和教师统一使用本机 `.env` 中的 `INITIAL_ACCOUNT_PASSWORD` 作为初始密码（至少 10 位），不要把实际值提交到 GitHub。教务创建成功后可在页面看到账号和初始密码，并交给本人；首次登录必须修改密码，此前不能使用选课或教学功能。已有账号不受影响，编辑档案不会重设密码。没有课表/授课/成绩或账号操作历史的档案可连同账号物理删除；有历史记录时应停用，避免破坏外键和审计。学生有开放学期的已提交课表时不能停用；教师仍认领着未结束学期教学班时不能停用或移除对应资格。已有的未绑定档案仍可用 `scripts.create_account` 手动建号。已有数据库升级前，用 Workbench 管理员连接执行一次 `database/10_initial_password.sql`；新装数据库的 `02_registration.sql` 已包含所需字段。不要重复执行迁移脚本。

英文题目中的 `social security number` 指美国社会保障号，不等于中国身份证号。教务端可以录入、替换或清除**虚构演示 SSN**；后端校验为 9 位数字，用 Fernet 加密后写入 `ssn_encrypted`，API 只返回“是否已填写”，不回显号码。不要输入真实身份证号或真实 SSN：本地 HTTP 演示并非真实个人资料系统。加密密钥由 `APP_SECRET` 派生，须妥善保管且不要随意更换，否则已存密文无法还原。旧版数据库已有 `identity_number_encrypted` 列时，请用 Workbench 管理员连接执行一次 `database/08_rename_ssn_fields.sql`；新装数据库直接执行最新版 `database/02_registration.sql`，不需要迁移。

选课正式关闭后，教务还需在真正教学结束时点击“确认学期教学结束”；这两个时点不同。成绩录入和学生成绩单只对应按年份、学季排序最新的**教学已完成学期**；其他历史学期不会混入当前成绩单。已有数据库需先在 Workbench 管理员连接执行一次 `database/09_term_completion.sql`；新装数据库的 `02_registration.sql` 已包含该字段。演示学期 `2026FA` 仍在开放中，不应提前关闭它来体验成绩功能。

同一页面还可创建草稿学期、设置选课时间和每学分演示费用，并在课程目录已有该学期教学班后开放选课。课程目录仍由外部系统维护，教务页面不会新增或修改课程。选课截止处理提供只读预览：无教师班先取消，然后按备选顺序补位，最后取消人数仍少于 3 人的班。**只有选课截止时间已过，才可输入学期代码确认正式关闭。**正式处理会重新计算，并在同一数据库事务里生成最终课表和待发送计费记录；如果失败则回滚。预览可能因其他人继续选课而变化。

演示学期 `2026FA` 的截止时间是 2026-10-15 23:59:59；在此之前不能正式关闭。不要为了演示而直接修改自己正在使用的学期时间。

## 本地模拟计费与重试

如果你之前已运行过 `02_registration.sql`，请先在 **MySQL Workbench** 用管理员连接执行一次 `database/07_billing_mock.sql`。它只新增 `mock_billing_receipt` 表，不修改已有学生课表或账单；新装数据库的 `02_registration.sql` 已包含这张表。没有执行迁移时，教务页面会提示执行该脚本。

正式关闭选课会把每名学生的最终课表和金额放入 `billing_outbox`。应用启动后会每 30 秒自动处理到期账单；教务页面“模拟计费发送状态”也可查看每笔的待发送、等待重试、成功状态，或手动立即处理到期账单。计费端以 `idempotency_key` 为唯一键保存收件记录；如果它已接收账单但确认消息丢失，再次发送同一账单只返回旧收件记录，不会重复计费。失败按 30、60、120 秒等间隔重试，最多间隔 10 分钟；服务重启后仍继续处理。**这只是本地模拟计费系统，不向真实财务系统发数据。**
