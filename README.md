# 课程注册系统（第五版本）

这是从零建立的独立项目，不依赖原来的 `course-registration-system` 代码。旧 Ingres 目录以只读 MySQL 演示库 `course_catalog_demo` 模拟；新系统的可修改数据在 `course_registration_v2`。目前完成学生登录与选课、教师认领教学班、教务档案与学期管理、选课截止处理、本地模拟计费发送/重试，以及教师成绩录入和学生成绩单。草稿不占名额；提交时在事务中检查先修课、主选时间冲突、开放时间和容量。开放期内学生可确认删除课表，已占名额在同一事务中释放。

## 获取当前版本

最新版在 GitHub 的 `第五版本` 分支，第四版基线保留在 `第四版本` 分支。获取最新版：

```bash
git clone --branch '第五版本' https://github.com/XinyueMa615/course-registration-system.git
cd course-registration-system
```

仓库在 GitHub 上叫 `course-registration-system`。已有仓库时，先保存本地改动，再运行 `git fetch origin` 和 `git switch --track origin/第五版本` 切换到最新版；已在 `第五版本` 分支时运行 `git pull origin '第五版本'`。

## 本机启动（macOS + VS Code）

1. 在 VS Code 打开刚克隆的项目目录，在其终端执行：

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

2. 确认 MySQL 正在运行。在 MySQL Workbench 中使用有建库权限的管理员连接。**全新、空白的本机数据库**按顺序打开并执行 `database/01_catalog.sql`、`database/02_registration.sql`、`database/03_demo.sql`。SQL 文件使用 UTF-8 编码；请执行整个脚本，使开头的 `SET NAMES utf8mb4` 先于中文数据写入语句运行。这会建立两个演示库并装入演示数据。已有本项目数据库时不要重跑 `03_demo.sql`：它会更新演示学期、课程目录和部分演示档案，不适合保留现有测试数据的场景；先用 `database/04_verify.sql` 查看现状。已有旧结构需要升级时，只执行缺少的迁移脚本（见下文），不要重建业务库。

   如果数据库里已经存入乱码，设置连接字符集不会自动修复旧记录。先备份并用 `database/04_verify.sql` 找出受影响的行，再从原始 UTF-8 数据恢复；不要直接重跑演示数据脚本覆盖现有记录。

3. 在 Workbench 打开 `database/05_permissions.sql.example`，把占位密码替换成你自己设置的强密码，再执行。该账号只可读取课程目录，并可读写业务数据库。不要提交填入真实密码后的 SQL。如果该账号已存在但密码不对，需在 Workbench 中单独修改密码；`CREATE USER IF NOT EXISTS` 不会重置旧密码。

4. 将 `.env.example` 复制为 `.env`，在 VS Code 中打开 `.env`：把 `DB_PASSWORD` 填成第 3 步设置的应用数据库密码，把 `APP_SECRET` 填成自己生成的随机长字符串（至少 32 字符），再设置本机统一初始密码 `INITIAL_ACCOUNT_PASSWORD`（至少 10 位）。以下命令只会打印一个可复制到 `APP_SECRET` 的随机值，不会自动写入 `.env`。`.env` 已被 Git 忽略，不能上传 GitHub，也不要使用别人的数据库密码或密钥。

   ```bash
   cp .env.example .env
   python3 -c 'import secrets; print(secrets.token_urlsafe(48))'
   ```

5. 演示库已有学生 `S001` 和教师 `P001`，但**没有默认登录账号密码**。在 VS Code 终端分别创建要测试的账号；脚本会提示你设置密码，输入时不会显示字符，也不会写入命令历史。教务账号不绑定学生或教师编号。已有账号不要重复创建。

   ```bash
   python3 -m scripts.create_account student1 STUDENT --person-id S001
   python3 -m scripts.create_account teacher1 PROFESSOR --person-id P001
   python3 -m scripts.create_account registrar1 REGISTRAR
   ```

6. 在项目根目录（能看到 `app/` 和 `requirements.txt` 的目录）启动服务。若终端当前不在该目录，先运行 `cd /你的路径/course-registration-system`；不要进入 `app/` 目录运行，也不要直接运行 `app/main.py`：

   ```bash
   python3 -m uvicorn app.main:app --reload --port 8001
   ```

   如果提示 `Could not import module "app.main"` 或 `No module named 'app'`，先执行 `pwd` 确认所在目录，再执行 `python3 -c 'import app.main; print(app.main.__file__)'` 检查当前 Python 能否找到项目包。使用虚拟环境时，确认已在同一终端执行 `source .venv/bin/activate`。

   保持终端运行，在浏览器打开 <http://127.0.0.1:8001/> 登录，不要直接用 `file://` 打开 HTML。三个明确入口分别为学生端 <http://127.0.0.1:8001/student>、教师端 <http://127.0.0.1:8001/professor>、教务端 <http://127.0.0.1:8001/registrar>；页面上的身份入口也可以相互切换。它们共用统一身份认证和同一个 8001 服务端口，登录后进入各自工作台：学生有“课程目录／选课／我的课表／我的成绩单”，教师有“教学班／名单与成绩”，教务有“学期与截止／计费状态／学生档案／教师与资格”。API 文档在 <http://127.0.0.1:8001/docs>。若本机的 8001 端口被占用，应先停止旧进程或另选端口并用相同端口访问。

### 已有数据库升级

全新安装只执行上述 `01_catalog.sql`、`02_registration.sql`、`03_demo.sql`，**不要再执行迁移脚本**。旧版数据库应先检查表和列，再按缺少的内容在 Workbench 管理员连接中执行：`07_billing_mock.sql` 增加模拟计费收件表；`08_rename_ssn_fields.sql` 把旧的 `identity_number_encrypted` 列改名；`09_term_completion.sql` 增加学期教学完成时间；`10_initial_password.sql` 增加首次登录改密标记；`11_fifth_version.sql` 创建 `auth_session` 并更新 `v_report_card`。`08`、`09`、`10` 不能重复执行；不确定是否已迁移时，先查看 Workbench 的表结构，不要直接重跑或重新建库。迁移不会自动复制你电脑里的账号、密码或选课记录到队友电脑。

学生选课页面会在填写课表时每 20 秒检查一次已选教学班的最新名额，并在主选已满或关闭时提示调整；点击提交前还会再次检查。真正占用名额的并发校验仍在数据库事务中进行，页面提示不能替代它。开放期内“删除课表”会先请学生确认，再删除选择并释放已提交主选的名额；截止后的最终课表不能删除。

## 教师端演示

演示库的教师 `P001` 已有 `CS101` 等课程的任教资格。首次运行时按上面的第 5 步为它创建教师账号。

打开 <http://127.0.0.1:8001/professor> 登录。原始演示数据的七个教学班都已预分配教师，因此最初只会看到“已认领”。要体验认领一个新班，可在 Workbench 用管理员连接执行 `database/06_teacher_demo_option.sql`。它只追加一个未认领的 `CS101-02` 班，不修改现有学生课表。刷新教师页面后即可认领；重复执行不会重复添加该班。当前课程目录来自独立的只读 MySQL 演示库 `course_catalog_demo`，用来模拟旧 Ingres 课程库；应用运行时不会写入该目录库。

认领会校验教师资格、选课时间、是否已有教师、教师本人其他教学班的时间冲突；教师只能退出自己认领的班。关闭选课后的认领与退出均被拒绝。

选课开放期间，教师可在自己认领的教学班点击“查看报名名单”，查看已经提交课表的学生；草稿学生不在名单中。教师不能查看其他教师的报名名单。

选课正式关闭、教务确认整个学期教学结束后，教师进入“名单与成绩”，在自己已认领且未被取消的教学班点击“查看名单与成绩”，查看最终学生名单并录入 A、B、C、D、F 或 I。可以暂时跳过学生；重复保存相同成绩不会新增记录，修改成绩会记录原成绩、新成绩、教师及时间。学生页面“我的成绩单”显示本人上一已完成学期的最终有效课程，尚未录入的成绩显示“待录入”。如果教师端提示学期已关闭选课但未确认教学结束，须由教务员在教学真正结束后完成确认，再刷新教师页面。`03_demo.sql` 初始设置的 `2026FA` 选课截止时间是 2026-10-15 23:59:59；当前本机数据库的实际状态以教务页面为准。

## 教务端演示

教务员账号在首次运行时按第 5 步创建，密码由创建者在终端交互输入。新建学生、教师档案时则由教务页面自动创建各自的登录账号。

打开 <http://127.0.0.1:8001/registrar> 登录。这里可以新增、查看、修改和确认删除学生/教师档案，并为教师添加或移除课程任教资格。新增时学号/教师编号按现有数据依次生成（如 `S005`、`P004`），同时自动建立对应的小写登录账号（如 `s005`、`p004`）；新建学生和教师统一使用本机 `.env` 中的 `INITIAL_ACCOUNT_PASSWORD` 作为初始密码（至少 10 位），不要把实际值提交到 GitHub。教务创建成功后可在页面看到账号和初始密码，档案列表也会持续显示登录名；首次登录必须修改密码，此前不能使用选课或教学功能。学生和教师登录后会显示本人姓名及编号。毕业日期表示实际毕业日期，仅在学生状态为“已毕业”时填写，不是系统预设的毕业时间。已有账号不受影响，编辑档案不会重设密码。没有课表/授课/成绩或账号操作历史的档案可连同账号物理删除；有历史记录时应停用，避免破坏外键和审计。学生有开放学期的已提交课表时不能停用；教师仍认领着未结束学期教学班时不能停用或移除对应资格。已有的未绑定档案仍可用 `scripts.create_account` 手动建号。

英文题目中的 `social security number` 指美国社会保障号，不等于中国身份证号。教务页面可录入或替换**虚构演示 SSN**，留空表示不修改；页面没有“清除 SSN”按钮。后端校验为 9 位数字，用 Fernet 加密后写入 `ssn_encrypted`，API 只返回“是否已填写”，不回显号码。不要输入真实身份证号或真实 SSN：本地 HTTP 演示并非真实个人资料系统。加密密钥由 `APP_SECRET` 派生，须妥善保管且不要随意更换，否则已存密文无法还原。

选课正式关闭后，教务还需在真正教学结束时点击“确认学期教学结束（开放教师录分）”；这两个时点不同。关闭后的教务页面会保留在“学期与截止”并提示这一步；教师页面在尚无已完成学期时也会显示等待确认的已关闭学期。成绩录入和学生成绩单只对应按年份、学季排序最新的**教学已完成学期**；其他历史学期不会混入当前成绩单。未确认教学结束时，教师无法录分。

同一页面还可创建草稿学期、设置选课时间和每学分演示费用，并在课程目录已有该学期教学班后开放选课。当前课程目录由独立的只读 MySQL 演示库维护，教务页面不会新增或修改课程。选课截止处理提供只读预览：无教师班先取消，然后按备选顺序补位，最后取消人数仍少于 3 人的班。**只有选课截止时间已过，才可输入学期代码确认正式关闭。**正式处理会重新计算，并在同一数据库事务里生成最终课表和待发送计费记录；如果失败则回滚。预览可能因其他人继续选课而变化。

`03_demo.sql` 给 `2026FA` 设置的初始截止时间为 2026-10-15 23:59:59；截止前不能正式关闭。若本机已通过教务操作调整或关闭该学期，以本机数据库实际状态为准，不要重跑演示脚本覆盖现有记录。

## 本地模拟计费与重试

旧版数据库缺少 `mock_billing_receipt` 表时，按“已有数据库升级”一节运行 `07_billing_mock.sql`。新装数据库的 `02_registration.sql` 已包含这张表。

正式关闭选课会把每名学生的最终课表和金额放入 `billing_outbox`。应用启动后会每 30 秒自动处理到期账单；教务页面“计费发送状态”也可查看每笔的待发送、等待重试、成功状态，或手动立即处理到期账单。计费端以 `idempotency_key` 为唯一键保存收件记录；如果它已接收账单但确认消息丢失，再次发送同一账单只返回旧收件记录，不会重复计费。失败按 30、60、120 秒等间隔重试，最多间隔 10 分钟；服务重启后仍继续处理。本地默认使用模拟计费系统，不向真实财务系统发送数据。

如果以后取得真实计费系统的 HTTP 接口，可在 `.env` 中切换：

```text
BILLING_MODE=http
BILLING_URL=https://billing.example.edu/api/registrations
BILLING_TOKEN=由计费系统提供的访问令牌
BILLING_TIMEOUT_SECONDS=10
```

系统会以 JSON `POST` 最终课表，并通过 `Idempotency-Key` 请求头发送稳定的幂等键。真实接收端必须按该键去重并返回 2xx；响应 JSON 可用 `{"duplicate": true}` 表示此前已经接收。接口地址、认证方式或响应协议不同的话，应在 `HTTPBillingReceiver` 中按对方正式文档调整后再联调。

## 测试与下一步

先在项目根目录运行不会写入数据库的常规测试：

```bash
python3 -m unittest discover -s tests -v
```

需要数据库的 7 项集成测试默认会显示 `skipped`，这是预期行为，**不等于它们已经通过**。这些测试会创建学生、课程、学期、账单等记录，部分还会关闭测试学期；不要在自己正在使用的 `course_registration_v2` / `course_catalog_demo` 上设置 `RUN_DB_INTEGRATION=1`。以后应先准备与当前数据隔离的专用 MySQL 测试实例，再在该实例运行这些测试。

人工联测建议按“教务建档并生成账号 → 学生／教师用初始密码登录并改密 → 学生保存草稿、提交和删除课表 → 教师查看报名名单 → 教务预览截止和模拟计费 → 教学结束后教师录成绩、学生看成绩单”的顺序进行。涉及关闭学期和录分的联测应使用隔离测试实例或专门准备的演示学期；本机 `2026FA` 已关闭选课，不能再用它测试开放期选课。重点检查越权访问、重复选课、满额、先修课与时间冲突。后续还需独立部署与性能验证；真实计费系统在获得正式接口资料后使用 HTTP 适配器联调。

项目提供了不依赖第三方工具的并发测试脚本。先启动服务，再通过环境变量提供测试账号，避免密码进入命令历史：

```bash
export LOAD_TEST_USERNAME=student1
export LOAD_TEST_PASSWORD='本机测试密码'

# 课程目录延迟冒烟测试
python -m scripts.load_test \
  --path '/api/catalog/offerings?term_code=2026FA' \
  --concurrency 50 --requests 500 --max-response 10

# 本地服务 500 并发测试
python -m scripts.load_test \
  --path '/api/catalog/offerings?term_code=2026FA' \
  --concurrency 500 --requests 2000 --max-response 10

# 2000 并发必须在专用压测机和隔离数据库执行
python -m scripts.load_test \
  --path '/api/catalog/offerings?term_code=2026FA' \
  --concurrency 2000 --requests 4000 --max-p80 120 --max-response 120
```

脚本输出成功率、吞吐量、P50/P80/P95 和最大响应时间，不满足阈值时以非零状态退出。`/health/live` 只检查进程存活，`/health/ready`（以及兼容入口 `/health`）同时检查业务数据库、课程目录和计费配置。完整的 500/2000 并发结论必须在独立、接近部署环境的服务器上获得，本机小规模结果不能代替正式容量测试。

`database/03_demo.sql` 仅用于本地演示，演示学期的选课时间截至 2026-10-15。过期后应配置新的演示学期和目录教学班，不应通过修改系统时间测试。

## 第五版本更新（相对上一版本）

以下内容以 GitHub `第四版本` 分支的提交 `150b588` 为对照；对应需求以 `需求总结.md` 为准。

1. **学生课程目录显示院系**：课程卡片同时显示课程代码、名称、学分和院系名称。对应需求是课程目录必须提供学生选课所需的完整课程信息。验证：学生登录后打开课程目录，检查每门课程均显示中文课程名和院系。
2. **区分空课表与不存在课表**：首次进入开放学期仍可创建空课表；要求已有课表的查询在课表不存在时返回 404。对应需求是资源不存在和合法空数据必须有不同语义。验证：首次加载使用 `?require_existing=false`；使用 `?require_existing=true` 查询未创建课表的学生，确认返回 404。
3. **服务端会话注销**：新增 `auth_session` 会话表、服务端撤销和 `/api/auth/logout`，注销后原令牌不能继续访问。对应需求是登录会话可注销且服务端能够立即失效。验证：登录取得令牌，调用注销，再访问 `/api/auth/me`，应返回 401；检查过期和已撤销会话不能通过认证。
4. **课程目录故障统一返回 503**：目录连接或接口不可用时统一返回服务暂时不可用，而不是泄露内部错误或返回 500。对应需求是外部只读课程目录故障需要稳定、可重试的错误语义。验证：停止或隔离课程目录库后请求 `/api/catalog/offerings`，确认返回 503，并恢复目录库后请求恢复成功。
5. **关闭注册互斥**：关闭学期注册时增加运行中检查和学期行锁，重复并发关闭只允许一个任务执行。对应需求是关闭流程必须事务化、幂等并防止并发破坏最终课表。验证：对同一学期并发发起两次关闭请求，确认只有一个成功执行，另一个得到“注册关闭正在处理”或等价冲突响应，数据库不产生重复运行记录。
6. **成绩单保留未录入成绩课程**：已完成学期最终课表中已确认且尚未录成绩的课程仍出现在成绩单，前端显示“待录入”。对应需求是成绩单显示上一已完成学期每个最终有效教学班及成绩。验证：确认教学结束后保留一门课程的空成绩，学生查看成绩单，确认课程存在且成绩显示“待录入”；录入成绩后显示对应字母成绩。
7. **页面写操作防重复点击**：学生、教师和教务端发出写请求时暂时禁用按钮，用统一状态阻止同一页面的重复请求。对应需求是操作状态清晰，避免重复选课、认领和写入。验证：快速连续点击写操作，确认页面只发出一次请求；最终一致性仍由后端事务和数据库约束保证。
8. **登录支持姓名并处理同名**：登录可使用用户名或姓名；姓名唯一时登录成功，同名时明确要求改用用户名。对应需求是满足账号登录和中文姓名登录，同时避免同名账号产生歧义。验证：分别用 `student1`、唯一中文姓名登录；准备两个同名账号后用姓名登录，确认返回 409 并提示使用用户名。
